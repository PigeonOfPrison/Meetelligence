# AI Approach

## Overview

The AI analysis workflow is responsible for generating meeting summaries, action items, decisions, and follow-up suggestions from meeting transcripts.

The implementation uses the Groq API with the `llama-3.3-70b-versatile` model.

To reduce unnecessary API calls, generated analyses are cached in the database and reused for subsequent requests.

---

## Prompt Design

The prompt was designed with a strong focus on grounding and hallucination prevention.

The model is explicitly instructed to:

* Use only information present in the transcript
* Avoid inventing attendees
* Avoid inventing decisions
* Avoid inventing action items
* Avoid inventing meeting outcomes
* Return output in a predefined JSON structure
* Return only JSON without additional explanations

The prompt also provides the required response schema to improve output consistency.

---

## Citation Strategy

The assignment requires all generated insights to be grounded in the transcript and include citations.

The prompt instructs the model to associate generated insights with transcript timestamps whenever possible.

Transcript segments are converted into the following format before being sent to the model:

```text
[00:10] John: We should launch next Friday.
[00:20] Alice: I will prepare release notes.
```

This structure makes timestamps directly available to the model and allows generated insights to reference the original source segments.

---

## Hallucination Prevention Approach

Several measures were taken to reduce hallucinations:

1. The model is explicitly instructed not to invent information.
2. The transcript is provided as the only source of context.
3. The required JSON structure limits the format of the response.
4. Meeting analyses are generated from stored transcript data rather than user-supplied free-form prompts.
5. The system does not provide external context or background information to the model.

These measures do not completely eliminate hallucinations but significantly reduce the likelihood of unsupported outputs.

---

## Output Validation Strategy

The AI response is expected to follow a predefined JSON structure.

After receiving the response from Groq:

1. The response is parsed.
2. The generated analysis is stored in the database.
3. The cached version is returned for future requests.

Future improvements could include schema validation to verify that all required fields are present before persisting the response.

---

## Analysis Caching

Generated analyses are stored in the `meeting_analysis` table.

If an analysis already exists for a meeting, the cached result is returned instead of generating a new one.

Benefits:

* Faster response times
* Reduced API usage
* Lower operational cost
* Consistent analysis results

---

## Known Limitations

* AI output quality depends on transcript quality.
* Citation accuracy is dependent on model behavior.
* The current implementation trusts valid JSON returned by the model and performs limited structural validation.
* If a transcript is modified after analysis generation, the cached analysis may become outdated.
* Action items generated by the AI are not automatically persisted as ActionItem entities and currently require manual review.

---

## Future Improvements

* Stronger JSON schema validation
* Automatic extraction and persistence of generated action items
* Confidence scoring for generated insights
* Multi-model evaluation and comparison
* Re-analysis when transcript content changes
* Support for multiple AI providers through a common abstraction layer
